# Чувствительность к реализации zlib

Локальный прогон 06.11.2026: группа Copter-4.7.2 плана `study-2026-11`, плата CubeOrange, сборка
интерпретатором Python 3.11.18, собранным с zlib-ng (`zlib.ZLIB_RUNTIME_VERSION` =
`1.3.1.zlib-ng`), машина с двумя ядрами. Тот же коммит, тот же тулчейн, чистая сборка.

Итог `not-reproducible`: образ на 112 байт длиннее официального, 1388 областей различий,
214 798 различающихся байт. Разбор по ELF (`diagnosis`): размером различаются только пять блоков
ROMFS, их распакованное содержимое совпадает с официальным — причина `romfs-compression`.

Та же сборка интерпретатором с классическим zlib 1.3.2 дала `.apj`, побитово совпадающий с
официальным; в основном прогоне в GitHub Actions эта плата собирается заново.
