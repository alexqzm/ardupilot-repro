# Каталоги сборочного сервера целиком

Запуск workflow `rebuild` [42290481338](https://github.com/alexqzm/ardupilot-repro/actions/runs/42290481338)
(06.11.2026, коммит `cadd1de`): группы Copter-4.4.4 и Plane-4.4.4 плана `study-2026-11`, плата
SPRacingH7 — 2 сборки. Все три каталога — те, что видны в официальном образе этой платы:

- дерево исходников — `/mnt/volume_nyc3_01/autotest/APM/APM`;
- каталог сборки — `/home/autotest/build/tmp/binaries.build` (`waf configure --out`; в образе —
  `/home/autotest/build/tmp/binaries.build/SPRacingH7`);
- тулчейн — `/home/autotest/arm-gcc/gcc-arm-none-eabi-10-2020-q4-major`.

Остальное — как в основном прогоне: GitHub Actions, `ubuntu-24.04`, Python 3.10.22 с zlib 1.3
(линейка 4.4 собирается Python 3.10), тот же архив тулчейна с проверкой SHA-256.

**Итог:** оба файла `.apj` побитово совпали с официальными (SHA-256 `a5832bd0…` для Copter и
`61863558…` для Plane). При штатной сборке в `build/` дерева эта плата не совпадает с
официальной: у неё вся прошивка исполняется из внешней флеш-памяти, и в загружаемой секции
`.text` официального образа лежат отладочные данные объектов startup и board ChibiOS с каталогом
сборки, каталогами тулчейна и путями к дереву относительно каталога сборки. Каким правилом
компоновки они туда попадают, не установлено; совпадение при тех же каталогах показывает, что
других отличий нет.
